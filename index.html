Fase 1 – Definición de la Nueva Funcionalidad

Sistema Predictivo de pruebas mediante Machine Learning

Departamento Desarrollo Ciencia de Datos Machine Learning

Esta fase define el alcance de la nueva funcionalidad aplicada a Vivo Group Pulse. El objetivo es analizar los datos históricos almacenados en Pulse_DB y VIVO_RIS para comprender el comportamiento de las pruebas médicas realizadas en los diferentes centros del grupo. A partir de este análisis se desarrollarán modelos de Machine Learning capaces de estimar el volumen futuro de pruebas médicas por clínica y modalidad. Las predicciones se visualizarán mediante gráficos predictivos integrados en la plataforma Pulse, facilitando la planificación operativa y la toma de decisiones empresariales.

Nombre completo del proyecto

Nombre completo del proyecto PULSE

Nombre completo de la funcionalidad:

Sistema Predictivo de pruebas para Vivo Group mediante Machine Learning

La funcionalidad propone desarrollar un sistema de análisis de datos capaz de utilizar información histórica de los datasets Pulse_DB para identificar patrones de comportamiento en las pruebas realizadas.

A partir de este análisis se construirán modelos predictivos que permitan estimar el volumen futuro de pruebas médicas por clínica y modalidad. Los resultados podrán visualizarse mediante gráficos predictivos dentro de la plataforma Pulse.

Actualmente Pulse ya dispone de una solución de inteligencia artificial proporcionada por un proveedor externo que permite realizar consultas sobre la base de datos y generar predicciones mediante una interfaz conversacional similar a ChatGPT.

La funcionalidad propuesta en este proyecto no pretende sustituir esa herramienta, sino complementarla mediante modelos propios enfocados específicamente a la visualización de predicciones en gráficos operativos dentro del sistema Pulse.

Introducción – Problema de negocio

Qué quiere saber la empresa

Contexto general

Vivo Group genera una gran cantidad de datos relacionados con su actividad médica y operativa. Sin embargo, estos datos se utilizan principalmente para análisis descriptivos, lo que limita su capacidad para anticipar tendencias futuras o mejorar la planificación estratégica.

Mediante técnicas de Machine Learning es posible analizar estos datos históricos para descubrir patrones de comportamiento y desarrollar modelos predictivos que ayuden a anticipar la demanda futura de pruebas médicas.

Decisión de negocio

La empresa busca aprovechar los datos disponibles en el dataset Pulse_DB para mejorar la planificación operativa y optimizar la toma de decisiones.

  • Identificar los factores que influyen en la actividad médica.
  • Predecir el volumen mensual de pruebas por clínica y modalidad.
  • Detectar patrones de comportamiento en los datos históricos.

Preguntas del proyecto

  • ¿Es posible predecir el volumen de pruebas futuras utilizando datos históricos?
  • ¿Existen patrones estacionales en la actividad médica?
  • ¿Qué centros o modalidades presentan mayor volumen de actividad?
  • ¿Cómo pueden utilizarse estos modelos para mejorar la planificación operativa?

Metodología

Marco CRISP-DM

La metodología del proyecto se inspira en el estándar CRISP-DM (Cross Industry Standard Process for Data Mining), un marco de trabajo utilizado ampliamente en proyectos de ciencia de datos y Machine Learning. Este enfoque permite estructurar el desarrollo del proyecto en distintas fases que conectan el análisis técnico con los objetivos de negocio.

Aplicar esta metodología facilita avanzar de forma ordenada desde la comprensión del problema empresarial hasta la implantación de modelos predictivos capaces de generar valor dentro del sistema Pulse.

1. Comprensión del negocio

En esta fase inicial se analiza el contexto de negocio de Vivo Group y las necesidades operativas relacionadas con la planificación de la actividad médica en los distintos centros del grupo.

El objetivo es identificar qué decisiones pueden beneficiarse de información predictiva. En este proyecto se plantea estimar el volumen futuro de pruebas médicas utilizando datos históricos con el fin de anticipar tendencias de demanda, mejorar la planificación de agendas y facilitar la asignación de recursos en los centros.

2. Comprensión de los datos

En esta fase se analizan las fuentes de información disponibles dentro del ecosistema de datos de Pulse con el objetivo de comprender la estructura de los datos y evaluar su idoneidad para el desarrollo de modelos predictivos.

Este proceso incluye la revisión de los datasets disponibles, la identificación de las variables relevantes para el análisis y la evaluación general de la calidad de los datos.

Análisis preliminar del dataset

Como parte de esta fase se ha realizado un análisis preliminar de la vista mv_forecast_general del sistema Pulse_DB, que contiene información histórica sobre la actividad médica de los centros.

El dataset analizado dispone de aproximadamente 7.674 registros con un histórico comprendido entre enero de 2023 y diciembre de 2026. Cada registro representa una combinación de clínica, modalidad de prueba y periodo temporal, lo que permite construir series temporales de actividad para cada centro y modalidad.

Durante este análisis preliminar se han evaluado aspectos como:

  • El rango temporal disponible de datos históricos.
  • El número total de registros disponibles.
  • Las variables presentes en el dataset (centro, modalidad, fecha, número de pruebas, etc.).
  • La calidad de los datos y la presencia de valores faltantes.

Los resultados de este análisis indican que el dataset dispone de suficiente volumen de datos históricos para entrenar modelos predictivos capaces de identificar patrones temporales, tendencias y posibles comportamientos estacionales en la actividad médica.

3. Preparación de los datos

Una vez comprendida la estructura de los datos, se procede a su preparación para el modelado.

Esta etapa incluye tareas como:

  • Limpieza y normalización de los datos.
  • Tratamiento de valores faltantes o inconsistentes.
  • Transformación de variables categóricas como centro o modalidad.
  • Creación de variables temporales relevantes (mes, año, estacionalidad).

El objetivo de esta fase es construir un dataset limpio y consistente que permita entrenar modelos de Machine Learning de forma fiable.

4. Modelado

En esta etapa se entrenarán distintos modelos de Machine Learning utilizando librerías como TensorFlow, Scikit-learn y herramientas de análisis de datos como Pandas.

El objetivo del modelado será generar estimaciones del volumen esperado de pruebas médicas en periodos futuros utilizando patrones observados en los datos históricos.

Los modelos analizarán la evolución temporal del volumen de pruebas para detectar tendencias, patrones estacionales y variaciones entre centros y modalidades.

Inicialmente se evaluarán diferentes enfoques de modelado con el fin de seleccionar aquel que ofrezca el mejor equilibrio entre precisión, interpretabilidad y facilidad de integración dentro del sistema Pulse.

5. Evaluación

Una vez entrenados los modelos, se evaluará su rendimiento utilizando métricas de error adecuadas para problemas de predicción temporal.

Además de las métricas técnicas, se analizará la utilidad práctica de las predicciones desde el punto de vista del negocio, verificando si los resultados pueden ayudar realmente a mejorar la planificación operativa de los centros.

Solo aquellos modelos que demuestren una mejora real respecto a métodos simples de estimación serán considerados candidatos para su implantación en el sistema.

6. Implantación

Una vez validado el modelo, se planteará su integración dentro del ecosistema tecnológico de Pulse.

El modelo se expondrá como un servicio interno accesible desde el backend de Pulse desarrollado en Quarkus. Este servicio permitirá generar predicciones bajo demanda mediante un endpoint de consulta.

Las predicciones generadas podrán representarse visualmente dentro de la interfaz de Pulse mediante gráficos interactivos desarrollados en Angular, permitiendo a los usuarios explorar tendencias futuras de forma intuitiva.

Las predicciones generadas se almacenarán en una tabla específica dentro de la base de datos Pulse_DB. Esta tabla contendrá las estimaciones de actividad futura por clínica, modalidad y periodo temporal, lo que permitirá que el backend de Pulse consulte los resultados de forma eficiente y los represente en gráficos dentro de la plataforma.

De esta forma el sistema puede mostrar los resultados de forma rápida y consistente dentro de la plataforma Pulse, evitando recalcular el modelo en cada petición realizada por los usuarios.

Infraestructura necesaria

La integración del modelo predictivo dentro de Pulse puede realizarse mediante un pequeño servicio de predicción desplegado como microservicio independiente.

La arquitectura general del sistema sería la siguiente:

  • Frontend: Angular, encargado de mostrar los gráficos predictivos.
  • Backend principal: Quarkus, responsable de la lógica de negocio y acceso a la base de datos.
  • Servicio de predicción: microservicio desarrollado en Python que ejecuta el modelo de Machine Learning.
  • Base de datos: PostgreSQL utilizada por el sistema Pulse.

El backend de Pulse realizará llamadas al servicio de predicción cuando sea necesario generar estimaciones de volumen futuro de pruebas. Los resultados se devolverán en formato estructurado y podrán representarse visualmente mediante gráficos dentro de la interfaz de usuario.

Requisitos de infraestructura

Para este tipo de modelos de predicción no es necesario hardware especializado. El modelo se ejecuta únicamente en modo inferencia, por lo que puede desplegarse en un servidor estándar dentro de la infraestructura existente.

  • CPU: 2-4 núcleos
  • Memoria RAM: 4-8 GB
  • Almacenamiento: 10-20 GB
  • GPU: no necesaria

El servicio puede desplegarse como un contenedor adicional utilizando tecnologías como Docker, integrándose con la infraestructura actual de Pulse sin requerir cambios significativos en la arquitectura existente.

Mantenimiento del modelo El modelo predictivo se reentrenará periódicamente utilizando los nuevos datos históricos disponibles en el sistema Pulse. Este proceso se realizará mediante un pipeline automático que entrenará nuevas versiones del modelo y evaluará su rendimiento antes de actualizar el modelo utilizado en producción. De esta forma se garantiza que el sistema predictivo se adapta a cambios en los patrones de actividad médica a lo largo del tiempo. En caso de degradación significativa del modelo, el sistema podrá utilizar métodos de estimación simples basados en datos históricos como mecanismo de fallback, garantizando así la continuidad del servicio de predicción.
